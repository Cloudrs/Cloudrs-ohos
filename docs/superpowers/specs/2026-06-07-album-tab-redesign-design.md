# 相册 Tab 重构设计稿

> 日期：2026-06-07
> 范围：`entry/src/main/ets/pages/tabs/TabPictures.ets` 的 UI 重构，及备份设置迁移到 `TabMine.ets`

## 1. 背景与目标

当前「相册」tab 实际是一个**照片备份**功能页（标题「相册备份」），整页是纵向 `List`：顶栏 → 概览卡(5 指标) → 上传中 → 待备份 → 失败 → 已完成 → 备份历史，设置面板从顶部齿轮展开。代码 2700+ 行，UI 与备份逻辑耦合在一个文件里。

**重构目标**：把这个 tab 从"备份管理面板"改造成一个**本地照片相册浏览器**——主体是本地图片的网格相册，每张图叠加同步状态；备份的进度/控制收进一个顶部抽屉；所有备份**设置**迁移到「我的」页。

**核心原则**：默认态尽量克制，几乎全是照片；备份相关 UI 退居次要、按需展开。

**保持不变**：底层备份引擎（扫描、上传队列、done-ids、断点、并发、Wi-Fi 限制、持久化等逻辑）全部保留，本次只重构展现层与设置入口位置。

## 2. 信息架构

```
相册 Tab (TabPictures)
├── 顶部栏：标题「相册」 + 右上角抽屉开关按钮（⌄/⌃）
├── 顶部进度抽屉（默认收起，点按钮滑下）
├── 分段切换：时间 | 相册
└── 照片网格主体（等高瀑布流，按分段维度分组）
        └── 点照片 → 大图预览页（带底部信息条）

我的 Tab (TabMine)
└── 更多设置区 新增一行「相册备份」 → 打开备份设置 sheet
```

## 3. 相册 Tab 详细设计

### 3.1 顶部栏

- 左：标题「相册」。
- 右：一个圆形按钮，**默认箭头朝下 `⌄`**（提示"点开进度"），抽屉展开后**箭头朝上 `⌃`**（提示"收起"）。同一个按钮，仅箭头方向随抽屉开合切换。
- 不再有齿轮/设置入口。

### 3.2 顶部进度抽屉

- **默认收起**，页面只有标题 + 照片，最克制。
- 点右上角按钮 → 抽屉从顶部**动画滑下**（`animateTo`，沿用项目既有动画时长 token）。
- 抽屉内容：
  - 总进度文案，如「正在备份 3 张」「已备份 112 / 128」。
  - 进度条。
  - **暂停 / 继续** 按钮（备份进行/暂停时）。
  - **立即备份** 按钮（空闲时手动发起一次扫描+备份）。
  - 三个计数：上传中 / 待备份 / 失败；其中**失败可点击触发重试**。
- **备份完成后抽屉自动收起**，回到纯照片态。
- 备份关闭时，抽屉展开后提示「备份已关闭」并提供「去开启」入口（跳转「我的 → 相册备份」）。

### 3.3 分段切换：时间 | 相册

- 位于抽屉下方、网格上方的分段控件（segmented）。
- **时间**：按拍摄/修改日期分组，置顶日期分组标题（今天 / 5月24日 / …）。
- **相册**：按本地相册分类分组（相机 / 截图 / 微信 / 下载 …），点进某个相册查看其中照片。
- 两个维度二选一切换；默认「时间」。

### 3.4 照片网格主体

- **排布**：等高瀑布流（justified rows）——保留每张图原始宽高比，按行铺满，类似 Google 相册。
- 分组标题随当前分段维度（日期 / 相册名）。
- **同步状态角标**（右下角小圆标）：

  | 状态 | 角标 |
  |---|---|
  | 已备份 | 云 ☁（半透明深底白色） |
  | 上传中 | 蓝色 ↑ |
  | 失败 | 红色 ! |
  | 本地未备份 | **不显示任何图标** |

- **关闭备份时**：已备份的图片**仍显示云☁角标**（"已备份"是这张图的客观事实，与是否开启自动备份无关）；不再出现"上传中/待备份"等进行态角标。

### 3.5 大图预览（方案 B：预览 + 信息条）

- 点网格中的照片 → 进入大图预览（复用并扩展现有 `ImagePreview.ets`），支持左右滑动切换。
- 黑底全屏，**底部常驻一条深色信息栏**：
  - 文件名
  - 时间、大小、尺寸
  - 备份状态与路径，如「☁ 已备份到 /Photos/Camera」；未备份 / 上传中 / 失败显示对应状态，失败态可点重试、未备份态可点「立即备份这张」。

### 3.6 边界与空状态

- **未授权相册权限**：显示空状态插画 + 「授权读取相册」按钮；授权后自动扫描。
- **备份关闭**：照常显示本地照片网格 + 已备份角标；抽屉展开提示「备份已关闭，去开启」。
- **本地无照片**：显示空状态文案。

## 4. 我的 Tab 设置迁移

### 4.1 入口

在 `TabMine` 的「更多设置」区，用既有 `rowWithNext` 样式新增一行：
- 图标：云 ☁；标题「相册备份」；副标题显示状态（如「已开启」/「未开启」）。
- 点击打开「相册备份」设置 sheet（沿用 `settingsSheet` 的 `bindSheet` 机制，新增一个 `MineSheetType.PHOTO_BACKUP`）。

### 4.2 备份设置 sheet 内容（从相册页迁移而来）

- **开启自动备份**（开关）
- **备份路径**（点开 `PathSelectSheet` 选择，沿用现有组件）
- **仅 Wi-Fi 下备份**（开关）
- **同时上传数量**（步进器，沿用现有 `concurrentStepButton`）

> 注：相册页不再保留任何设置项；自动备份开关本身也在这里。

## 5. 架构与代码组织

当前 `TabPictures.ets` 2700+ 行，UI 与逻辑混在一起。本次重构借机做有针对性的拆分（不做无关重构）：

- **保留**：备份引擎相关方法（扫描、合并、done-ids、上传队列、持久化、权限、缩略图加载等）继续承载业务逻辑。
- **抽取**：将备份状态/设置的数据与方法从 UI struct 中下沉到一个可复用的 model/controller（例如 `PhotoBackupController`），使相册页与「我的」设置 sheet 共享同一份备份状态来源（设置在「我的」改动后，相册页抽屉/角标能同步反映）。
- **新增 UI 组件**（建议各自独立文件，便于聚焦）：
  - 顶部进度抽屉组件
  - 等高瀑布流网格组件（含分组标题、状态角标）
  - 时间/相册分段组件
  - 大图预览信息条（扩展 `ImagePreview`）
- **设置项**：在 `TabMine` 中新增「相册备份」sheet，复用 `PathSelectSheet`、`concurrentStepButton` 等既有部件。

> 共享状态方案的具体载体（AppStorage / 单例 controller / @ObservedV2）在实现计划阶段确定，须保证「我的」页改设置与相册页展示的一致性。

## 6. 不在本次范围

- 不改动底层上传/下载传输实现（`RequestUpload` / `RequestDownload`）。
- 不浏览/拉取云端图片（主体仍是**本地**照片）。
- 不改动备份的去重、断点、路径历史等业务算法。
